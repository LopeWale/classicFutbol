# Player-to-player collision, contact and personal space in EA FIFA / EA SPORTS FC and Konami PES / eFootball

Scope: FIFA 10 → EA SPORTS FC 27 (FC 27 shipped Sept 2026, so it is included where it bears on the questions) and PES 2010 → eFootball 2026 (v5.x). Every number is tagged **[official]** (EA/Konami statement, patent text or patch note), **[community]** (reviewer/forum observation), or **[estimate]** (my inference). Title each mechanism belongs to is stated in brackets. Audience: a deterministic 60 Hz fixed-point sim with capsule players and procedural animation, so the emphasis is on rules, radii, priorities and resolution logic rather than rendering.

## KQ1. FIFA 12 Player Impact Engine: what it did, what broke, and how EA refined/replaced it (FIFA 12 → 13 → 14 → Frostbite/HyperMotion → FC)

### Takeaway
The Player Impact Engine (FIFA 12, PS3/360) replaced pre-authored, binary collision animations with a real-time multi-body physics model that monitored every contact point on each player's body and let physics resolve the collision using per-body-part mass/torque and joint strength; it produced the famous "catapult/broken limb" glitches because joint strengths were unrealistic and the system had never been exposed to millions of players. EA's fix path was: re-tune joint strengths (FIFA 13), add a predictive "anti-collision" layer so players avoid or brace before contact (FIFA 14 next-gen "Pro Instincts"), rewrite locomotion to make feet/momentum honest (FIFA 14 "Precision Movement"), and then progressively move contact outcomes back toward animation-driven, attribute-gated systems ("Natural Collision System" FIFA 21, "Player Awareness" collision prediction FIFA 23, reworked Shielding/physics FC 26, Off-Balance Dribbling FC 27). No "Precision Physics" branding for FC 24 could be found.

### Inferences
- The Impact Engine was a full articulated-rigid-body contact solver layered over mo-cap (consistent with EA's own 2005 patent on playing mocap "using forces on physical models", see KQ2). Its failure mode (over-strong joints → energy injection → catapults) is a classic constraint-stiffness problem; the FIFA 13 fix was parameter re-tuning, not an architectural change.
- From FIFA 14 onward EA's answer to "players run into each other" was predictive avoidance (change the action state before contact) rather than better physics. Every later generation re-states the same three-part pattern: (1) predict running paths, (2) step/jump over fallen bodies, (3) if contact is unavoidable, pick a glancing animation that reduces impact.
- By FC 26, EA explicitly treats the avoidance layer itself as a source of sticking, and tunes tangential friction ("slippery") plus a lateral separation nudge — directly reusable in a capsule sim.
- Contact outcome has steadily migrated from "let physics decide" (FIFA 12/13) to "attribute comparison gates which animation plays" (FIFA 19 50/50, FC 25 fatigue-scaled shielding, FC 27 Balance/Agility/Dribbling-gated off-balance state). For a deterministic sim this is good news: outcomes can be table/rule-driven.

## KQ2. Collision avoidance BEFORE contact: steering, personal space, yielding, EA patents

### Takeaway
EA's public statements describe a predictive avoidance layer (FIFA 14 Pro Instincts, FIFA 21 Natural Collision System "understanding of running paths", FIFA 23 "collision prediction system") and EA's 2025 patent US 12,268,964 ("World prediction within a game application environment") spells out the mechanism: run the world forward in several frame-offset instances, test coarse "farfield" boxes (max motion over N frames), then only for overlapping pairs test "nearfield" boxes for limbs, and feed a predicted collision into the agent's action state so it begins avoiding. No EA patent explicitly claims teammate-yield or personal-space radii for football; Konami, by contrast, holds patents that specify a teammate-yield rule (move teammates out of a radius-R "decision area" around the controlled player's target by distance L) and a priority-ordered destination-assignment rule that prevents two teammates targeting one space.

**EA patents (assignee Electronic Arts Inc.)**
- **US 12,268,964 B2 – "World prediction within a game application environment"** (granted 8 Apr 2025). Claim 1: predicting a collision by "determining if overlap occurs between individual bounding boxes of the two or more virtual objects, in response to a determination that the individual bounding boxes ... overlap, generating at least one nearfield bounding box for each ... and determining if overlap occurs between the ... nearfield bounding boxes". Description: the module "may use a defined number of instances (such as, for example, 2, 5, 8, 10 ...) to predict player collisions. Each instance may represent the game environment offset by a set number of frames (e.g., the first instance is the game environment offset by four frames, the second instance is offset by eight frames, and so on)". A "farfield bounding box ... represents the predicted range of motion for a virtual object over a time period, such as a set number of frames (e.g., four frames)", built from "a vector representing the velocity of the centroid ... and a total distance the virtual object may reach". A "nearfield bounding box ... represents a range of motion for a subcomponent of a virtual object (e.g., hands, arms, legs, etc.)". Objects with no farfield overlap are deleted from the pipeline; predicted collisions are written to the agent's "action state" so "the next action may be to avoid the collision" ("update the action state of an agent to cause the agent to begin avoiding the predicted collision"). [official patent; frame numbers are patent examples] — [Google Patents US12268964B2](https://patents.google.com/patent/US12268964B2/en)
- **US 10,692,266 B2 / US 10,984,573 B2 – "Collision detection and resolution in virtual environments"** (Lewin; priority GB 2018). Claim: compute each primitive's displacement from velocity, project both onto the separating direction, compute "a predicted minimum distance ... based on the projection of the first displacement ... the second displacement ... and the initial distance", and "in response to the predicted minimum distance being less than a threshold distance, generat[e] a collision constraint preventing penetration"; dependent claims: "the threshold distance is based on a static collision radius" / "a radius associated with at least one of the ... primitive[s]". Field is stated as soft-body/cloth, but the test is generic continuous-collision for points/capsules. [official patent] — [USPTO US10692266](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/10692266)
- **US 7,403,202 B1 – "Computer animation of simulated characters using combinations of motion-capture data and external force modelling"** (Nash, filed 2005). [official] — [USPTO](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/9180371)

### Inferences
- For a 60 Hz deterministic sim, the EA world-prediction scheme maps to: every tick (or every 4 ticks), for horizons h ∈ {4, 8, 12, …} frames, build a per-player swept disc (centroid + v·h·dt + stride margin) → broadphase overlap → for overlapping pairs only, check capsule/limb sweep → write a "predicted-contact(h, other, relative-velocity)" flag into the player's decision state so steering/animation chooses "check run / swerve / brace / jump" before contact. This is cheap, deterministic, and avoids needing physics at all for the common case. [estimate]
- Lewin's "predicted minimum distance along the separating direction vs. radius" is exactly a one-step continuous-collision test for capsules and is a clean deterministic way to decide "will touch this tick" without tunnelling. [estimate]
- Konami's teammate-yield rule is the clearest published "personal space" rule: a radius R around the controlled player's destination is reserved; teammates inside it are pushed radially outward by L (not toward the ball), with an angular fallback and a teamwork-scaled reaction delay. The same rule works for a CPU ball carrier if "controlled player" is replaced by "ball carrier". [estimate]
- Konami's destination-priority assignment prevents two runners targeting the same space (the exact bug eFootball later patched, see KQ7): greedy assignment in priority order, one player per destination, ties by travel time. [estimate]

### Gaps
- No EA patent could be found that claims teammate-yield radii, velocity-obstacle style avoidance, or "one presser" rules for football; EA SEED publishes on path following for vehicles, not footballers.
- EA has never published numeric personal-space radii, look-ahead horizons or avoidance priorities for FIFA/FC; the only concrete numbers are the frame-offset examples in US 12,268,964.

### Inferences
- Resolution rule reconstructable from the above: (1) contact event classified by geometry — side-by-side vs. from-behind vs. head-on; (2) from-behind → foul probability up, high relative velocity → foul up, "soft" contact → no foul; (3) winner by attribute comparison (Strength primary; fatigue scales shielding; PlayStyle bonus; relative size now under review in FC 27); (4) loser gets a stumble/off-balance state whose severity is reduced by Balance/Agility; (5) repeated inputs degrade the challenger (speed loss). All are deterministic given inputs and seeded RNG. [estimate]
- Shielding body placement is a target-pose rule, not physics: the shielder orients so the capsule sits on the segment between ball and nearest opponent, dribbles with the far foot, and "backs in" when pushing toward the opponent — i.e., velocity toward the opponent is converted to a slow push with the ball dragged behind. [estimate]
- Animation is paired/synced mo-cap with a small physics overlay ("physics effects for both shielder and shieldee"), not a capsule/ragdoll hybrid, since FIFA 14. For a procedural-animation sim the equivalent is: a shared "contact frame" (midpoint, normal) that both players' IK targets reference, with a low-amplitude displacement proportional to the strength delta. [estimate]

### Gaps
- EA never publishes the strength/balance formula, the foul thresholds, or the contact normal/relative-speed limits. The only official numeric gates found are the AcceleRATE attribute thresholds.
- Whether modern FC uses capsules, convex hulls or per-bone volumes for player–player contact is undocumented.

## KQ6. CPU-vs-CPU separation: minimum spacing, lane assignment, "one presser" rules

### Takeaway
Neither company publishes spacing numbers, but published patents and patch notes show the mechanisms: Konami restricts automatic "press defense" to a region whose depth from the goal line scales with score difference and lifts the restriction after a timeout (≈10 s), limits which defender is selected to approach the ball, assigns teammates to open-space destinations one-per-destination in priority order, and pushes teammates out of the controlled player's target radius. EA's FC IQ Player Roles (FC 25+) and repeated patch notes ("avoid clashing with teammates", "two forwards almost same position" on Konami's side) show the same intent: run assignments are de-duplicated and defenders mark/press by role rather than all chasing the ball.

### Cited Findings

[estimate]
- The "swarm" failure in a home-grown sim usually comes from every defender using the same utility (distance to ball). Both franchises' fixes are to make the press slot exclusive and the rest positional.

### Gaps
- No official minimum-separation distance, lane width, or number of simultaneous pressers is published by EA or Konami. The only hard numbers are patent examples (10 s override) and eFootball's 70% speed statement.

## KQ7. Known failure modes and how they were fixed (checklist for a sim that shows players running into each other)

### Takeaway
The recurring, documented failure modes are: physics catapults from over-stiff joints (FIFA 12), players tangled/stuck together (FIFA 19 community, eFootball v3.4.0, v5.0.0, FC 26), avoidance itself causing sticking or unwanted slowdown (FC 26, FC 26 TU), teammates clashing on runs or occupying the same spot (FC 26 TU, eFootball v5.0.0), pile-ups on fallen players/keepers (FIFA 21, FC 26, eFootball v5.0.0), oversized collision volumes (eFootball v5.4.0), and size-mismatched collisions (FC 27, open). The fixes are consistently rule-based: predict and steer early, step over bodies, cap avoidance friction, separate laterally, de-duplicate destinations, and gate stumbles by relative velocity/attributes.

### Inferences (recommended rule set for a deterministic 60 Hz capsule sim, synthesised from the sources)
1. **Predict, don't collide.** Every 4 ticks, for horizons 4/8/12 frames, sweep each player's capsule along v·h (EA US 12,268,964). Only on broadphase overlap compute Lewin-style predicted minimum distance along the separating axis vs r1+r2. Write (partner, h, closing speed, approach angle) into the decision state. [estimate from patents]
2. **Avoidance responses by role** (FIFA 14/21/23 behaviours): off-ball runner → check run or swerve; chaser → side-step/jump over grounded body; ball carrier → auto-dribble around (disabled only when user locks off-ball, per FC 27). Avoidance steering should use low tangential "friction" so two avoiding players slide past rather than stall (FC 26 "slippery").
3. **Teammate yield radius** (Konami US 2010/0240429): reserve radius R around the carrier's/controlled player's target; teammates inside are displaced by L along the radial from target to teammate, rotating by θ if out of bounds; delay by teamwork. Treat a grounded keeper or a keeper with the ball as a reserved zone too.
4. **One destination per runner** (Konami US 8,616,946): prioritise open spaces, assign greedily by travel time, never two players to one slot (fixes the "two forwards same position" bug).
5. **Exclusive presser** (Konami US 8,398,487; eFootball Defensive Engagement): one engager selected by time-to-ball and stat; press suppressed in a region that shrinks when losing, overridden after a timeout; others hold role slots; off-ball cruise ≤ ~70% max speed.
6. **Contact gates**: initiate shield/charge only within a distance gate; shoulder challenge valid side-by-side; from-behind or ball-in-air → foul/suppressed; spamming → speed loss (FC 27, eFootball).
7. **Outcome by attributes, not impulse**: compare Strength/Physical Contact (+fatigue, PlayStyle, size); loser enters stumble whose severity is reduced by Balance/Agility and which can keep directional control (FC 27 Off-Balance); apply a small symmetric displacement along the contact normal to both bodies (FC 26 "physics for shielder and shieldee"); reset possession lockout after dispossession (eFootball v5.0.0).
8. **Overlap resolution**: push apart along the contact normal only, add a lateral nudge if relative velocity ≈ 0 for N frames (FC 26 "moved to the side"), keep collision radius ≤ visual radius (eFootball v5.4.0), make hands non-colliding with the ball (FIFA 21).

### Gaps
- No franchise publishes the relative-velocity or angle thresholds that distinguish "soft contact" (no foul, no stumble) from a stumble-inducing collision; these must be tuned empirically.
- EA's open FC 27 investigation into size-mismatched collisions means even the market leader does not have a settled rule for mass/height asymmetry.
